# Mapa de contradicciones entre la autoridad y el agente actual

Base auditada: `028f272` (observaciones de la baseline) sobre la línea de código presente en `647b317`.

Este mapa separa tres situaciones:

- **CONTRADICCIÓN:** el código decide estrategia o comportamiento que la autoridad reserva al Agente A, o puede cortar una venta válida.
- **RIESGO COMPUESTO:** la regla de hechos/efectos es válida, pero depende de una capability que mezcla las nueve reglas autorizadas con condiciones adicionales; puede rechazar una decisión comercial válida.
- **COMPATIBLE:** valida hechos, efectos, consentimiento, idempotencia o entrega. Se incluye cuando apareció en las observaciones para no confundir un control permitido con una contradicción.

“Bloquea” significa que la regla aparece como rechazo en ese turno de la baseline v3, aunque una reparación posterior haya permitido aprobar el turno. Los códigos y subjects se conservan por separado en el resultado v3.

## Lectura operativa

1. Los controles de precio canónico, cursos existentes, logística respaldada por `fact_id`, consentimiento, deduplicación, idempotencia, opt-out y estado de pago pertenecen al backend.
2. `CALL_OFFER_REQUIRED`, `price_objection_reframe` y `persistent_price_objection` deciden cómo vender; por eso contradicen de forma directa `AGENTS.md:25-27`.
3. `forbidden_promise` es correcto cuando una de las nueve reglas falla. Es incorrecto si la única causa es una condición adicional escondida dentro de `may_offer_bonus`.
4. Aunque el rechazo original sea válido, convertir una reparación fallida en silencio contradice `prompt-agente-a-studyx-v2.md:236`. El sistema debe conservar la intención comercial y responder con la alternativa autorizada.
5. La baseline v3 atribuye la capa al componente que emitió el rechazo: cualquier turno fallido con `backend_rejections` queda en `validador` y conserva cada `code/subject` exacto.
